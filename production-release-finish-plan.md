# Finish the ResearchingOS production release

Goal: ship a measured, recoverable, single-operator research workspace. Public multi-user SaaS is a separate release requiring tenant authorization and isolated data/jobs/artifacts. Preserve FastAPI, React, SQLite, the durable queue and isolated workers unless measurements justify replacing them.

Baseline: `docs/release-completion-checklist.md` records 381 backend tests, four frontend tests, build and local HTTP checks passing; this planning pass did not rerun them. Live workflow, public HTTPS and off-host recovery remain blocked. Never reset the original ledger: $5 cap, $4.794125 reserved, $0.205875 available at the recorded checkpoint.

## Ordered work

Each checkbox is a workstream; execute it as small, independently checked changes. Keep statuses and receipts in the existing completion checklist. Complete independent local work while external inputs are pending.

- [ ] **1. Freeze scope and acceptance contract.** Record approved server/FQDN/TLS method, encrypted backup/restore targets, alert recipient, reviewed research inputs and provider configuration; confirm budget without assuming an increase. Proposed targets: one operator, one API process, queue cap 100 per managed DB, 10 concurrent browser requests, 24-hour RPO, one-hour RTO. Verify private configuration without copying secrets into evidence.
- [ ] **2. Make a clean checkout reproducible.** Audit every loader/build input against tracked source/dependency locks; fix missing release-evidence links and commercial-use restrictions in `integrations/research_skills.json`. Add CI checks for locks, lint, source integrity and isolated-image smoke; review dependency/image scans and licenses. Verify frozen backend/frontend installs and digest-pinned image builds from a clean checkout; publish sanitized CI receipts tied to commit and image digest.
- [ ] **3. Close security and resource gaps.** Audit all model/tool/legacy routes, downloads and vault access; apply authentication, shared reservations, admission limits, bounded uploads/tool outputs and execution deadlines consistently. Cover login and Basic-auth attempts, SSRF/redirects, retrieved prompt injection, generated-code escape, session expiry and secret redaction. Verify rejected anonymous/foreign-origin requests and malicious fixtures; no credential leakage or unauthorized host/network access.
- [ ] **4. Make failures operable.** Add job-correlated structured logs/metrics, queue-age/disk/budget/provider/backup alerts and operator runbooks. Define artifact/job retention and safe coordinated snapshots; document schema upgrade/rollback and interrupted-call reconciliation. Verify restart/duplicate submission/provider outage/disk-full/queue-full probes: no lost accepted job, stale overwrite, ambiguous paid-call replay or corrupted historical download; test one alert end to end.
- [ ] **5. Qualify live research.** Pre-register a small reviewed corpus with held-out labels and manuscript citation map; test OpenResearch → Harness² → AlphaEvolve adapter → council → PaperOrchestra → reviewed publisher bundle, including independent candidate replay. Record provider/model/prompt/input versions, costs, failures, exact citations and hashes. Pass: completed bounded stages, verifiable outputs, no invented citations, independent numeric-claim review, required venue compilation and original-revision downloads. BLOCKED if conservative total reservations exceed remaining allowance; do not shrink checks merely to claim success.
- [ ] **6. Deploy authenticated HTTPS.** Render `deploy/` templates for the approved existing host; validate service/proxy configuration, loopback API binding, firewall, private permissions, rootless runtime and hard disk quota. Verify secure-cookie login, logout/expiry, all four HTTP surfaces, `/api/ready`, SSE reconnection, a completed download and tamper rejection through the public hostname. Rehearse rollback to the previous application/images with compatible state.
- [ ] **7. Prove off-host recovery.** Back up coordinated vault, artifacts, all databases, original ledger, revision/image manifest and encrypted private configuration. Restore to the approved isolated target with provider egress disabled. Verify every hash, SQLite integrity, queued/interrupted recovery, historical downloads and service startup; measure RPO ≤24h and RTO ≤1h. A second directory on the same Mac does not satisfy this gate.
- [ ] **8. Final verification and release decision.** On the release commit, run full backend/frontend/CI checks, real-browser critical journeys, image probes and a 30-minute staged soak at the agreed load. Proposed control-plane targets: p95 health/job-status <1s, unexpected HTTP errors <1%, explicit 429 overload, no lost jobs/process/container leaks; measure research completion separately against task deadlines. Record rollback result and scientific review; scan, commit, push and confirm remote SHA and CI. Publish the evidence matrix, remaining risks and operator handoff.

## Done and stop rules

**RELEASE COMPLETE** requires all eight workstreams passed with receipts for the same release candidate and completed scientific review. **LOCAL WORK COMPLETE — BLOCKED** means feasible local work passed and each external gate names its exact missing input. **WORK INCOMPLETE** means a fixable implementation/check failure remains. Finish with one headline, commit/push/CI status and owned-process cleanup; stop after the report. Never imply a plan or passing unit tests certify production.
